# F-01 章节标题识别格式测试样本库

来源:预注册验收单(`../acceptance_2026-07-26/预注册验收单.md`)第 5 节 F-01,用户 2026-07-26 反馈——真实 txt 的章节标题格式五花八门,识别层必须覆盖常见变体,识别不确定时给候选并走基线 4.3「待确认」通道,正式产品不能要求用户编辑源文件。

## 内容

- `samples/s01…s18.txt`:18 个格式变体样本。正文均为本库自撰的中性填充文字(无版权内容);`s05_longzu_regression` 仅复用本次验收实际踩坑的两个标题格式作回归用例。
- `manifest.json`:与样本同一脚本产出(`脚本存档见本文件末尾`),每个样本记录:
  - `current_recognizer`:改造前基线(依据 `backend/app/services/source_import.py` 的 `_CHAPTER_LINE`/`_HEADING` 正则,2026-07-26 实测)——仅作记录,不参与判定;
  - `expected_units`:改造后必须产出的单元序列(类型/标题片段/置信级);
  - `assertions`:附加断言(防误切、前置区归属、待确认通道等)。

## 判定规则(全绿才算数)

1. 每个样本导入后,单元序列与 `expected_units` 逐一匹配(类型、标题包含、数量);
2. `confidence=candidate` 的单元必须出现在 4.3 待确认队列,**不得静默硬切**;`high_if_sequence` 按 manifest 中 `confidence_semantics` 判定;
3. `assertions` 逐条成立,尤其 `s14`(正文孤立数字/列表不误切)是防回归的负例锚点;
4. 实现落地时应将本库整体搬进代码仓库测试目录(如 `backend/tests/fixtures/chapter_formats/`)做成 pytest 参数化用例;研究目录这份是权威原始版本。

## 生成脚本

样本与 manifest 由本目录 `gen_f01_samples.py` 同源产出以保证一致性;如需增补样本,直接在脚本 `SAMPLES` 结构里加条目重跑即可(重跑会整体覆盖 `samples/` 与 `manifest.json`,README 手工维护)。
