# AI 小说拆解工作台

这是“AI 小说拆解工作台”的公开开发仓库。产品目标、页面、用户流程、参考机制、真实进度和开发顺序统一以 [当前基线 V1.0](docs/CURRENT_BASELINE.md) 为准。

当前仓库已经完成 P0 工程地基，并形成从整本导入到深层拆解的内部首条闭环，但尚未达到最终用户验收条件。人物、事件、故事结构、事实状态和核心分析已经进入同一工作台；长篇材料超过模型安全上下文时会自动执行“连续章节范围 → 阶段 → 全书”的来源链保真聚合。首轮约 75 万字真实样本的工程验收已经通过，内容质量仍为“需要复核”；人物身份人工裁决、最小金标真实读数以及更多题材与篇幅样本仍需完成，不能把当前内部版本当作最终产品：

- TXT、Markdown、DOCX、EPUB 整本导入与章节确认
- 在线模型服务、模型目录和任务分析方案
- 第一版人物与事件候选及原文证据回查
- 故事总览、人物角色、剧情阶段和事件关系
- 事实有效区间、状态变化、人物认知和世界规则
- 伏笔、冲突、场景、节奏及支持/反证分离的分析主张
- 工作台全局搜索、指定章节状态、问题标记、重新分析和版本差异
- 新书共创第 0～9 步内部候选流程：可把每一步带到任意网页 AI 讨论，检查固定阶段结论并维护五份标准结果文件；已通过内部模拟，但尚未经过用户真实新书共创验收
- 可恢复任务、重试、取消和幂等制品
- Windows 一键安装、启动和完整自动测试
- 普通工作台与 `/debug` 内部调试入口分离

> 当前各模块成熟度和下一步统一查看 `docs/CURRENT_BASELINE.md`，不再用一个总百分比掩盖差异。


## 0. 环境要求

- Windows 10/11
- Git
- Python 3.12 或 3.13
- Node.js 20 或更新版本（包含 npm）

## 1. Windows 快速启动

日常使用请双击项目根目录的 `启动AI小说拆解工作台.bat`。

启动后会保留一个可见的工作台窗口。这个窗口负责页面、后台服务和任务执行器的完整生命周期；关闭窗口会一并关闭它们，不会留下本项目的后台进程。

关闭浏览器标签页不会停止正在进行的长篇分析；需要彻底关闭系统时，关闭这个启动窗口即可。

首次安装或开发调试时，在项目根目录打开 PowerShell：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup.ps1
```

安装完成后关闭 PowerShell，再双击 `启动AI小说拆解工作台.bat`。

正式启动后：

- 工作台：`http://127.0.0.1:15173`
- 新书共创（第 0～9 步内部候选流程）：`http://127.0.0.1:15173/new-book`
- API 文档：`http://127.0.0.1:18000/docs`
- 健康检查：`http://127.0.0.1:18000/health`

`dev.ps1` 仅用于开发调试，会分别启动 API、Worker 和 Frontend；日常使用不要通过它启动。

## 2. 开发人员验证后台闭环

下面的操作只用于开发人员验证后台，不是小说拆解流程，最终用户无需验收：

1. 在页面创建项目。
2. 打开 `/debug` 创建一个 `fake.echo` 测试任务。
3. Worker 领取任务并生成不可变 JSON Artifact。
4. 页面刷新后可看到任务状态由 `PENDING` 变为 `SUCCEEDED`。
5. Artifact 文件写入 `workspace/artifacts/<project_id>/`。

## 5. 当前开发入口

42 问全量原料审计、逐问增量答案编译和首组反馈基础修复闭环已经完成；学习答案每问一个独立模型任务。4.9 已恢复为“全书章末钩类型与节律”，数百至上千章按连续窗口覆盖；3.4 已成为独立的“前三章章末钩—首次回应—章距/字距”账本，所有实际钩子找到首次回应后立即停止，仍有未回应钩子时才扫描到全书末尾。2.1 已成为第一个具备逐项合同验收的问题：程序负责人数、首行动序、后续量级、新增间隔、功能分布和身份风险，模型只返回逐人首场功能类别；真实精简运行输入 73,297 Token（令牌）、输出 3,485 Token，113 人不重不漏，27/55/113 与 28 个引入批次均由程序编译。2.2 和 4.9 现已支持局部接受、局部修复：六个人物字段或逐章结果中只有一处客观错误时，正确部分保留在原任务，下一轮只请求错误字段或章节。程序继续校验身份、证据、引文、数量、范围、顺序、覆盖和无数据外部因果，不再用欲望深度、动机关键词、钩类型/强度分歧或正常读者指称等主观门槛拒绝整份结果。先前 79,582/165,478 Token 双臂和 164,030 Token 固定事实探针仍作为历史诊断证据：24/24 客观事实正确，漏答根因是旧合同、原料、返回结构和验收错位，不是已证明的长输入注意力下降。学习答案的所有已配置模型和核心 42 问统一采用 15 万 Token 单次请求软上限；它是默认天花板，不是目标输入量，模型上下文更小时自动收紧，4.9 等局部专项也可主动使用更小窗口。3.4 在 75 万字符样本上原计划 10 个窗口，找到第三章钩子的首次回应后实际只运行 2 个窗口，总输入 210,476 Token（分属两次各自低于上限的请求），其余 8 个自动取消。学习页仍按八阶段目录一次只读一问，完整账本默认折叠；远程和中转全部流式，本机学习报告等长任务也强制流式。下一步是用新合同刷新已过期的 1.4、2.2、4.9 用户答案、恢复依赖 4.9 的 3.4 当前状态并完成 AI 自检，通过后再进入 QG-1 的 3.1/3.2 专项原料。完整合同、真实进度和后续顺序只在 [当前基线 V1.0](docs/CURRENT_BASELINE.md) 维护。
